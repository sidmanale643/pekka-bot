    01The run

    See every step. Nothing happens out of sight.

    Every step streams as it happens: what the model says, which tool it calls, what came back. You can follow a run in the CLI, the web app or over the HTTP API.

    1. a
      It plans, then acts

      The agent loop sends your task and its tools to the model, runs each tool call, and feeds the results back until the job is done.

    2. b
      It stops to ask

      Before a write, a send or a risky command, it shows you the exact arguments and waits for a yes.

    3. c
      It tells you what it cost

      Each run ends with the step count, tokens used, cache hit rate and the cost the provider reported.

    03Features

    Built for real work. And built to be trusted with it.

    Bots that remember, keep their own files, run on a schedule and never act behind your back.

    A computer that stays put

    Each bot works in its own persistent Linux sandbox on Daytona. It stops after 15 idle minutes and starts again with its files intact.

    Nothing changes without a yes

    Reads run on their own. Writes, sends and risky commands wait for one-time approval of the exact arguments, and expire after five minutes.

    08FAQ

    Common questions

    Anything else is probably in the README.

    01How is Pekka different from a chat assistant?

    A chat assistant tells you what to do. A Pekka bot does it: it runs the commands, writes the files and uses your connected tools itself, then reports back. It keeps its workspace and memory between tasks and can run on a schedule.

    02Does every bot get its own computer?

    Yes. Each named bot has its own persistent Daytona sandbox, plus its own memory and skills. Sandboxes stop after 15 idle minutes and start again on the next task with their files intact.

    03What can a bot do without asking?

    Read: files, memory, skills, web searches, read-only plugin calls, and a short allowlist of shell commands such as ls and cat. Everything else, including other commands, file and memory writes, schedule changes and anything that sends or publishes, needs one-time approval of the exact arguments.

    04Which models can I use?

    Any OpenRouter model that supports tool calling. Set PEKKA_MODEL to pick one.

    05Can my team share one server?

    Yes. Turn on Google sign-in and list the addresses or domains allowed in. Each person gets their own bots, memory, schedules and plugin connections.

    06What does it cost?

    Pekka is free and open source. You pay OpenRouter for model usage, Daytona for sandboxes, and any optional providers you turn on.

    07What can't it do yet?

    Bots can't drive a web browser or hand work to each other yet, and email is send-only for now. Scheduled tasks run while the pekka scheduler process is running.
